# 堆排序（Heap Sort）详解

## 概述

堆排序是一种基于**二叉堆**数据结构的比较排序算法。它分两个阶段：先将数组建成最大堆，再反复将堆顶最大值"提取"到数组末尾，最终得到升序序列。

- **时间复杂度**：O(n log n)（建堆 O(n)，每次提取 O(log n)，共 n 次）
- **空间复杂度**：O(1)（原地排序，递归调用栈深度 O(log n)）
- **稳定性**：不稳定

---

## 核心概念：二叉堆的数组表示

把完全二叉树存在数组里，下标关系如下：

```
        arr[0]
       /       \
   arr[1]     arr[2]
   /    \     /    \
arr[3] arr[4] arr[5] arr[6]
```

| 节点下标 `i` | 左子节点 | 右子节点 | 父节点 |
|:-----------:|:-------:|:-------:|:-----:|
| `i`         | `2i+1`  | `2i+2`  | `(i-1)/2` |

**最大堆性质**：每个父节点的值 ≥ 它的左右子节点的值。堆顶 `arr[0]` 始终是当前最大值。

## 代码逐步解析

### 入口函数 `HeapSort`

```go
func HeapSort(arr []int) []int {
    n := len(arr)
    if n <= 1 {
        return arr
    }
    ...
}
```

**为什么**：元素个数 ≤ 1 时，本身就有序，直接返回，避免无意义操作。

---

### 第一阶段：建堆（Build Max-Heap）

```go
for i := n/2 - 1; i >= 0; i-- {
    heapify(arr, n, i)
}
```

**为什么从 `n/2 - 1` 开始？**

数组下标 `n/2` 到 `n-1` 的节点都是**叶子节点**（没有子节点），它们天然满足堆性质，不需要处理。

只有下标 `0` 到 `n/2 - 1` 的节点才有子节点，需要执行"下沉"。

**为什么从后向前？**

从底层非叶子节点开始，先让下层子树满足堆性质，再处理上层节点。这样当处理某个节点时，它的子树已经是合法的最大堆了，`heapify` 才能正确工作。

**会发生什么（以 `[4, 10, 3, 5, 1]` 为例）：**

```
初始数组：[4, 10, 3, 5, 1]
        4
       / \
     10   3
    /  \
   5    1

n=5, 从 i=1 开始（n/2-1 = 1）

i=1: heapify([4,10,3,5,1], 5, 1)
  root=1(值10), left=3(值5), right=4(值1)
  largest=1(10最大), 不交换
  数组不变：[4, 10, 3, 5, 1]

i=0: heapify([4,10,3,5,1], 5, 0)
  root=0(值4), left=1(值10), right=2(值3)
  largest=1(10最大), 交换 arr[0] 和 arr[1]
  数组变为：[10, 4, 3, 5, 1]
  递归 heapify([10,4,3,5,1], 5, 1)
    root=1(值4), left=3(值5), right=4(值1)
    largest=3(5最大), 交换 arr[1] 和 arr[3]
    数组变为：[10, 5, 3, 4, 1]

建堆完成：[10, 5, 3, 4, 1]
        10
       /  \
      5    3
     / \
    4   1
```

**结果**：数组变为合法最大堆，`arr[0]=10` 是最大值。

---

### 第二阶段：逐步提取最大值

```go
for i := n - 1; i > 0; i-- {
    arr[0], arr[i] = arr[i], arr[0]
    heapify(arr, i, 0)
}
```

**为什么交换 `arr[0]` 和 `arr[i]`？**

`arr[0]` 是当前堆中的最大值，把它放到 `arr[i]`（当前未排序部分的末尾）就相当于把最大值"固定"到了它最终该在的位置。

**为什么之后调用 `heapify(arr, i, 0)`？**

交换后，堆顶变成了原来的末尾元素（较小值），打破了堆性质。`heapify` 让它从堆顶"下沉"到合适位置，恢复堆性质。注意堆的有效范围是 `[0, i-1]`（`i` 之后的元素已排好序，不参与）。

**会发生什么（继续上例，堆为 `[10, 5, 3, 4, 1]`）：**

```
i=4: 交换 arr[0] 和 arr[4]
  数组：[1, 5, 3, 4, | 10]  （|后为已排好序部分）
  heapify([1,5,3,4], 4, 0)
    root=0(值1), left=1(值5), right=2(值3)
    largest=1(5最大), 交换 arr[0] 和 arr[1]
    [5, 1, 3, 4, | 10]
    递归 heapify 下标1：
      root=1(值1), left=3(值4), right=4(越界)
      largest=3(4最大), 交换 arr[1] 和 arr[3]
      [5, 4, 3, 1, | 10]
  
i=3: 交换 arr[0] 和 arr[3]
  数组：[1, 4, 3, | 5, 10]
  heapify([1,4,3], 3, 0)
    largest=1(4最大), 交换
    [4, 1, 3, | 5, 10]
    递归下标1：left=3(越界), 不交换

i=2: 交换 arr[0] 和 arr[2]
  数组：[3, 1, | 4, 5, 10]
  heapify([3,1], 2, 0)
    left=1(值1), right=2(越界)
    largest=0(3最大), 不交换

i=1: 交换 arr[0] 和 arr[1]
  数组：[1, | 3, 4, 5, 10]
  heapify([1], 1, 0) → 只有1个元素，无操作

最终结果：[1, 3, 4, 5, 10]
```

---

### `heapify` 下沉函数

```go
func heapify(arr []int, n, root int) {
    largest := root
    left := 2*root + 1
    right := 2*root + 2

    if left < n && arr[left] > arr[largest] {
        largest = left
    }
    if right < n && arr[right] > arr[largest] {
        largest = right
    }

    if largest != root {
        arr[root], arr[largest] = arr[largest], arr[root]
        heapify(arr, n, largest)
    }
}
```

**每一行为什么这么写：**

| 代码 | 原因 |
|------|------|
| `largest := root` | 先假设当前节点已经是三者中最大的 |
| `left := 2*root + 1` | 二叉堆数组公式，左子节点下标 |
| `right := 2*root + 2` | 二叉堆数组公式，右子节点下标 |
| `left < n` | 必须检查越界，叶子节点没有子节点 |
| `arr[left] > arr[largest]` | 找出三者中最大值的下标 |
| `if largest != root` | 如果 root 已经是最大的，堆性质满足，无需操作 |
| `heapify(arr, n, largest)` | 交换后被换下去的节点可能又比它的子节点小，递归修复 |

**递归终止条件**：当 `largest == root`（当前节点已是子树最大值）或节点已是叶子节点（`left >= n`）时自然终止。

## 完整执行流程图

```
原始数组：[4, 10, 3, 5, 1]

【建堆阶段】
→ [10, 5, 3, 4, 1]  ← 合法最大堆

【提取阶段】
→ [5, 4, 3, 1, | 10]   第1次提取
→ [4, 1, 3, | 5, 10]   第2次提取
→ [3, 1, | 4, 5, 10]   第3次提取
→ [1, | 3, 4, 5, 10]   第4次提取

【最终结果】
→ [1, 3, 4, 5, 10]  升序排列完成
```

---

## 复杂度分析

### 建堆阶段：O(n)

虽然有 n/2 个节点需要 heapify，但底层节点下沉距离短，顶层节点少，数学求和结果是 O(n)，而非直觉上的 O(n log n)。

### 提取阶段：O(n log n)

执行 n-1 次提取，每次 heapify 的代价是 O(log n)（树高），总计 O(n log n)。

### 总体：O(n log n)

无论最好、最坏、平均情况，堆排序都是 O(n log n)，不像快速排序在最坏情况下退化为 O(n²)。
