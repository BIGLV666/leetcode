# 44. 通配符匹配（Hard）

**题目链接**: <https://leetcode.cn/problems/wildcard-matching/>

## 核心思路

`'?'` 匹配任意单个字符，`'*'` 匹配任意字符串（**含空串**），判断 `p` 能否完整匹配 `s`。
仓库里给了两种解法（`isMatch` 贪心、`isMatchII` 记忆化），结果一致。

**解法一（贪心 + 回溯）**：`'*'` 能吃任意长度，但没必要枚举——先让它匹配空串往前走；
一旦后面失配，就回到**最近一个 `'*'`**，让它比上次多吞一个字符再试。
关键在于：失配时永远只回退到「最近的 `'*'`」就够，不需要更早的 `'*'`——
更早的 `'*'` 能吞的字符，最近的 `'*'` 都能替它吞（贪心正确性的核心）。

**解法二（记忆化递归）**：`check(i1, i2)` 表示 `s[i1..]` 与 `p[i2..]` 能否匹配，
状态数 `O(|s|·|p|)`、每状态 O(1) 转移，是最不会写错的兜底写法。

## 算法流程

解法一的四个分支（`i1` 走 s、`i2` 走 p）：

1. 普通字符或 `'?'` 能对上：两边同时前进；
2. 遇到 `'*'`：记 `start = i2`（星号位置）、`mark = i1`（当时的 s 位置），
   然后 `i2++`——相当于先让它匹配空串；
3. 失配且 `start >= 0`：`i2 = start + 1`（回到星号后一位），`mark++`（星号多吞一个），
   `i1 = mark`，重新匹配；
4. 失配且没有星号可退：返回 false。

s 耗尽后，p 剩下的部分必须**全是 `'*'`** 才算匹配。

解法二的转移：

```text
i2 == |p|          -> 匹配 ⟺ i1 == |s|（p 耗尽时 s 必须也耗尽）
p[i2] == '*'       -> check(i1, i2+1)  或  i1 < |s| 且 check(i1+1, i2)
其他且字符能对上   -> check(i1+1, i2+1)
否则               -> false
```

## 正确性说明

- 贪心的回溯只退最近一个 `'*'` 是安全的：设更早还有 `'*'`，它多吃一个字符的
  效果等价于最近 `'*'` 多吃一个字符（两者中间的部分由普通字符匹配决定），
  所以「最近的星号多吞一个」覆盖了所有需要重试的情形；
- 解法二里 `i2 == |p|` 时必须检查 `i1 == |s|`——只写 `return true` 会漏掉
  "s 还剩字符" 的情况，这是本题最常见的写挂点。

## 复杂度

- 贪心：均摊接近 `O(|s| + |p|)`，最坏（大量 `'*'` 反复回溯）`O(|s|·|p|)`；空间 `O(1)`。
- 记忆化：状态 `O(|s|·|p|)`，转移 O(1)，时间空间均 `O(|s|·|p|)`。

## 易错点

1. `'*'` 匹配**空串**也要算——先按空串前进、失配再回溯，漏了空串分支就错；
2. 贪心里回溯点 `mark` 忘了 `++`，会死循环在同一个位置；
3. s 走完后要检查 p 剩余部分全为 `'*'`，而不是直接返回 true；
4. 记忆化表每次调用都要重开（实例字段复用时残留旧结论）；
5. `'? '` 与 `'*'` 语义不同：`'?'` 恰好一个字符，不能匹配空串。
