# 115. 不同的子序列（Hard）

**题目链接**: https://leetcode.cn/problems/distinct-subsequences/

## 核心思路

计数型双序列动态规划（本题解用记忆化搜索实现）。定义 `dfs(i, j)`：`t` 从 `j` 起、`s` 从 `i` 起时，`t[j:]` 在 `s[i:]` 中作为子序列的出现次数。答案即 `dfs(0, 0)`。

为什么能拆成子问题：考虑 `s[i]` 要不要参与匹配 `t[j]`——

- **不用 `s[i]`**：问题化为 `dfs(i+1, j)`；
- **用 `s[i]` 匹配 `t[j]`**（仅当 `s[i] == t[j]`）：两者同时消耗，问题化为 `dfs(i+1, j+1)`。

两种选择对应不同的匹配方案，互不重叠又覆盖所有可能，直接相加即是无后效性的正确转移。所有状态 `O(n·m)` 个、每个 `O(1)` 转移，记忆化后不重复计算。

## 算法流程

1. `j` 越过 `t` 末尾：`t` 已全部匹配完，返回 `1`（正好构成一种方案）。
2. 剩余的 `s` 比剩余的 `t` 短（或 `i` 越界）：不可能再匹配，返回 `0`——这是关键剪枝，避免大量无效递归。
3. 否则累加 `dfs(i+1, j)`；若 `s[i] == t[j]` 再累加 `dfs(i+1, j+1)`。

## 正确性说明

- 边界 1 把「t 匹配完」计为一种方案，而此时 s 剩余部分原封不动，天然满足「子序列保持相对顺序」。
- 每一层只决策 `s[i]` 的用与不用，任何一种匹配方案都唯一对应一条「用/不用」决策链，因此计数不重不漏。
- 剩余长度剪枝只是提前返回必为 0 的状态，不影响计数。

## 复杂度

设 `n = len(s)`、`m = len(t)`。记忆化搜索共有 `O(n·m)` 个状态，每个状态 `O(1)` 转移，时间 `O(n·m)`；缓存表空间 `O(n·m)`，加上递归栈 `O(n+m)`。

## 易错点

- **剪枝条件别只写 `i >= len(s)`**：不加「剩余 s 短于剩余 t 就返回 0」时递归树会多出一整层「s 耗尽但 t 没匹配完」的无效分支，量大时明显变慢（写不写都正确，但容易超时）。
- **两个边界判断的先后**：必须先判 `j >= len(t)` 再判 `s` 耗尽。若 s 与 t 同时耗尽，应返回 `1`（完全匹配）而不是 `0`，顺序反了会把所有完全匹配漏计。
- **用 `lru_cache` 时 `dfs` 必须定义在 `numDistinct` 内部**，让缓存随每次调用重建；若提到类外或模块级，跨用例的缓存虽按参数区分不会算错，但会白白驻留内存。
- 转移里「跳过 `s[i]`」是**无条件**的，匹配成功只是**额外**多一条路；写成二选一（`else`）会漏掉「既不用 `s[i]` 也能在后面再匹配 `t[j]`」的方案。
