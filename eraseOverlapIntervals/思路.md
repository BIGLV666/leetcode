> Problem: [435. 无重叠区间](https://leetcode.cn/problems/non-overlapping-intervals/description/)

[TOC]

# 思路

> 你选用何种方法解题？

**贪心(区间调度问题)+ 转换视角**。

「移除最少的区间使剩余互不重叠」等价于「**保留最多**的不重叠区间」——总数固定,保留得越多移除得越少。而"最多不重叠区间数"正是经典的区间调度问题,有著名的贪心解:

**按右端点升序排序,能保留就保留。**

直觉:每保留一个区间,都会占掉一段"空间";想让后续保留得尽量多,就应该让每个被保留的区间**尽早结束**(右端点尽量小),给后面留出最大的余地。

反证:若最优解中第一个保留的区间不是右端点最小的那个,把它换成右端点最小的,它不会与后面任何区间产生新冲突(它的右端点更小),保留数不减——贪心不劣。

# 解题过程

> 这些方法具体怎么运用？

1. **按右端点升序排序**(比较器用 `Integer.compare`,避免减法溢出的惯性写法)。
2. **顺序扫描**,维护 `preR` = 上一个被保留区间的右端点(初始 `Integer.MIN_VALUE`):
   - 若 `p[0] >= preR`:与保留集无冲突,**保留**,更新 `preR = p[1]`;
   - 否则 `p` 与某个已保留区间重叠,**移除**——注意不更新 `preR`,这是贪心的核心(继续用当前最小的右端点去接纳后面的区间)。
3. **答案 = 总数 − 保留数**。

两个易混细节:

- **端点相触不算重叠**:题面明确 `[1,2]` 与 `[2,3]` 不重叠,所以保留条件是 `>=` 而不是 `>`。
- **冲突时为什么不动 `preR`**:被移除的区间右端点一定 `>= preR`(排序保证),保留它只会让后续更难接;维持现有 `preR` 才是最优决策。

# 复杂度

- 时间复杂度: $O(n \log n)$ —— 排序主导,扫描是 $O(n)$。
- 空间复杂度: $O(\log n)$ —— 排序递归栈。

# 易错点

1. **比较器溢出**:`a[1] - b[1]` 在坐标范围大时(如 LC 452 的 ±2³¹−1)会溢出回绕导致排序错乱,统一写 `Integer.compare(a[1], b[1])`。
2. **`>=` 与 `>`**:端点相触算不算重叠由题面决定,435 是"不算";写反会把合法区间也移除。
3. **转换方向**:直接贪"移除哪些"很难(要考虑移除后腾出的空隙),转成"保留最多"才是标准区间调度。

# Code

```Java []
class Solution {
    public int eraseOverlapIntervals(int[][] intervals) {
        Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1])); // 按右端点升序
        int ans = 0;              // 能保留的区间数
        int preR = Integer.MIN_VALUE; // 上一个保留区间的右端点
        for (int[] p : intervals) {
            if (p[0] >= preR) {   // 端点相触不算重叠,故用 >= 保留
                ans++;
                preR = p[1];
            }
            // 否则 p 与保留集重叠,移除 p(不更新 preR,贪心核心)
        }
        return intervals.length - ans;
    }
}
```
