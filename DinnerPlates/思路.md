# 1172. 餐盘栈（Hard）

**题目链接**: https://leetcode.cn/problems/dinner-plate-stacks/

## 核心思路

**双有序集合维护栈位** — 用数组保存每个栈，再用两个 `TreeSet` 分别记录「还有容量的栈下标」与「非空栈的下标」，使三类操作都能在 `O(log m)` 内找到目标栈。

- `push(val)`：取 `indexSet` 的最小下标（最左侧未满栈）压入；没有可用栈时新建一个。压入后该栈若已满，从 `indexSet` 移除；同时把它加入 `havingSet`。
- `pop()`：取 `havingSet` 的最大下标（最右侧非空栈）弹出；弹空则从 `havingSet` 移除，否则该栈一定腾出了容量，加入 `indexSet`。
- `popAtStack(index)`：下标越界或该栈为空返回 `-1`，否则直接弹出栈顶，并按同样规则同步两个集合。

## 算法流程

```text
push(val)         : indexSet 为空 → 新建栈并压入；否则取最小下标压入，满则移出 indexSet
pop()             : havingSet 为空 → -1；否则取最大下标弹出，空则移出 havingSet，非空则补回 indexSet
popAtStack(index) : 越界或空栈 → -1；否则弹出并同步两个集合
```

## 正确性说明

- `indexSet` 恒为「未满栈」的集合：新建栈未满就加入，压满就移除，弹出后必然腾出空间就补回，因此 `push` 取到的一定是最左侧未满栈。
- `havingSet` 恒为「非空栈」的集合：压入后加入，弹空后移除，因此 `pop` 取到的一定是最右侧非空栈。
- 两个集合都只在下标真实存在时包含它，故 `queue.get(index)` 不会越界。

## 复杂度

- 时间复杂度：设当前栈数为 `m`，每次操作为 `O(log m)`。
- 空间复杂度：`O(n)`，`n` 为元素总数（两个集合最多各存 `n` 个下标）。

## 易错点

- 出栈腾出容量后必须把下标补回 `indexSet`，否则以后 `push` 会错误地新建栈。
- `pop` 的目标是「最右侧非空栈」，不是「最后创建的栈」：中间的栈被弹空后，最后创建的栈可能已不是最右非空栈。
- 新建栈时若容量为 1，压入即满，不能再加入 `indexSet`。
- `popAtStack` 遇到越界下标或空栈要返回 `-1`，不要抛异常。
