# 2267. 检查是否有合法括号字符串的路径（Medium）

**题目链接**: https://leetcode.cn/problems/check-if-there-is-a-valid-parentheses-path/

## 核心思路

网格里每格是 `(` 或 `)`，只能向右或向下走，问是否存在一条从 (0,0) 到 (m-1,n-1)、沿途括号恰好配平的路径。

把"路径"与"括号配平"两个约束拆开：向右/向下的路径只看端点，括号配平只看**净括号数**（`(` 记 +1，`)` 记 -1，全程不为负、终点为 0）。于是状态只需 `(行, 列, 当前净括号数)` 三元组——到达同一格且净括号数相同的两条路径，对后续完全等价，可以记忆化。

## 算法流程

`dfs(r, c, count)` = 从 (r, c)（含本格）出发、当前净括号数为 count 时，能否走到终点并配平：

1. 越界 → false；
2. 本格加入 count，若 count < 0 → false（关键剪枝：净括号数一旦变负，此后怎么补都救不回来）；
3. 到终点 → 返回 count == 0；
4. 否则递归向右、向下，任一可行即 true。

## 正确性说明

- 净括号数 < 0 的路径必然不合法（括号序列前缀不能右括号多于左括号），剪掉不影响答案。
- 状态压缩的依据是马尔可夫性：后续是否合法只取决于"在哪个格子"和"当前净括号数"，与走到这里的历史无关，记忆化不漏不重。
- 终点判 `count == 0` 对应括号完全配平；中途不判终点是因为路径必须走满整条。

## 复杂度

净括号数取值范围是路径长度 `m + n - 1` 级别，状态数 `O(m·n·(m+n))`，每个状态 O(1) 转移；记忆化搜索时间即 `O(m·n·(m+n))`，空间同阶（缓存 + 递归栈 O(m+n)）。

## 易错点

- **净括号数必须进状态**：只按 (行, 列) 记忆化会把"到达同一格但括号余额不同"的路径错误合并——这是本题最容易犯的错。
- `count < 0` 要在递归**入口处**就剪，否则负数状态会大量进缓存拖慢搜索；还可以再加"count 大于剩余步数"的上界剪枝，本题实现没写也能过。
- **别把 `linecache.cache` 当成 `functools.cache`**：`from linecache import cache` 导入的是一个**字典**（模块内部缓存），拿来当 `@cache` 装饰器会立刻 `TypeError: 'dict' object is not callable`。装饰器要用 `from functools import cache`（这个仓库的 numDistinct.py 也踩过一次）。
- 路径长度是 `m + n - 1`：如果它是奇数，可以直接判 false（括号配平要求偶数长度），本题实现没有这条剪枝，靠终点 `count == 0` 兜住正确性。
