# 76. 最小覆盖子串（Hard）

**题目链接**: <https://leetcode.cn/problems/minimum-window-substring/>

## 核心思路

滑动窗口。`table` 记 t 的字符需求（字符 → 需要几个），`map` 记当前窗口的字符计数：

- 右端 `r` 每步纳入一个字符（扩窗）；
- 窗口一旦**覆盖** t（对 t 的每个字符 `c` 都有 `map[c] >= table[c]`），
  就记录答案，并不断把左端 `l` 出窗、试图找到更短的覆盖窗口；
- 左端出窗直到窗口不再覆盖，回到扩窗。

"覆盖"判断没有手写循环，而是让内部的 `Table`（继承 `HashMap`）**重写 equals**：
`map.equals(table)` 的语义改为「`table` 里的每个 key 都有 `map[k] >= table[k]`」，
主循环里一句 `while (map.equals(table))` 就是覆盖判断。

## 算法流程

```text
① 统计 table = t 的字符需求
② r 从左到右扫描:map[s[r]]++
③ while (map 覆盖 table):
      若窗口长度 r-l+1 更短,记录 ans 与 res = s[l..r]
      map[s[l]]--，l++（缩左端）
④ 返回 res（从未覆盖过则空串）
```

## 正确性说明

- 窗口覆盖时继续缩左端是安全的：更短的窗口只可能在「当前覆盖窗口去掉左端字符」
  里出现，右端再往右只会更长；
- 每个字符进出窗口各一次，左右端单调右移，所以是线性而不是平方；
- `Table.equals` 的方向：遍历的是**需求方**（table）的 entry，检查窗口方（this）
  的计数是否 `>=` 需求；窗口里有而需求里没有的字符不影响覆盖（方向写反是
  这份实现曾经踩过的坑）。

## 复杂度

时间 `O(|s| + |t|)`：左右端各单调走一遍，每次覆盖判断 `O(|t|)`；
空间 `O(字符集大小)`。

## 易错点

1. 覆盖是**多重集**比较：t 里有重复字符时，窗口里的数量必须同样多，
   只判"出现过"会漏；
2. `equals` 的比较方向（谁遍历谁）——遍历需求方、检查窗口方，写反会对"窗口多出的字符"误判；
3. 覆盖判断成立的 while 里要先记录答案再缩左端，顺序反了会漏掉当前窗口；
4. 无解（t 比 s 长、或某字符根本不出现）返回空串，别返回 null；
5. `Table` 重写 equals 后与 hashCode 语义不再一致，这个对象不能当 HashMap 的键使用。
