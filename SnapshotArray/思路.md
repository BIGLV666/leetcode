# 1146. 快照数组（Medium）

**题目链接**: https://leetcode.cn/problems/snapshot-array/

## 核心思路

**历史版本 + 二分查找** — 每个下标维护一个修改历史列表，查询时二分查找目标快照 ID 对应的值。

### 数据结构

每个下标 `index` 对应一个 `[]change` 切片，每条记录 `{snapID, value}` 表示"在快照 snapID 时该位置的值变为 value"。

### 操作

- **Set (index, val)**: 若同一 snapID 内已有修改（即历史列表末尾记录的 snapID 等于当前 snapID），则 **原地覆盖**
  而不是新增记录。否则追加新记录。
- **Snap ()**: 返回当前 snapID，然后 snapID 自增 1。
- **Get (index, snapID)**: 在 `history[index]` 中二分查找 **第一条 snapID > 目标 snapID 的记录**的位置 pos。若 pos ==
  0（没有任何 ≤ 目标 snapID 的修改），返回默认值 0；否则返回 `records[pos-1].value`。

## 复杂度

- **时间复杂度**: Set O (1)，Snap O (1)，Get O (log M)，其中 M 是该位置的修改次数。
- **空间复杂度**: O (N + M)，N 为数组长度，M 为 Set 总调用次数。

## 易错点

1. 同一 snapID 内多次 Set 需原地覆盖，否则历史列表会冗余膨胀。
2. 二分查找找的是"第一个 > snapID"的位置，返回的是前一条记录的值。
3. 初始值 0 不需要显式存储，查询时 pos == 0 即返回 0。
