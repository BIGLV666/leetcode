> Problem: [550. 游戏玩法分析 IV](https://leetcode.cn/problems/game-play-analysis-iv/description/)

[TOC]

# 题意

`Activity` 表记录玩家登录(游戏)记录,主键 `(player_id, event_date)`。

求:**首次登录的第二天也登录了**的玩家数 / 玩家总数,保留 2 位小数。

```text
原始数据(LC 官方示例)
+-----------+-----------+------------+--------------+
| player_id | device_id | event_date | games_played |
+-----------+-----------+------------+--------------+
| 1         | 2         | 2016-03-01 | 5            |  ← 玩家 1 首次
| 1         | 2         | 2016-03-02 | 6            |  ← 次日又登录 ✓
| 2         | 3         | 2017-06-25 | 1            |  ← 只登录过一天
| 3         | 1         | 2016-03-02 | 0            |  ← 玩家 3 首次
| 3         | 4         | 2018-07-03 | 5            |  ← 隔了两年,不是次日 ✗
+-----------+-----------+------------+--------------+
答案:1 / 3 = 0.33
```

# 思路

> 你选用何种方法解题？

所有解法都围绕**同一个三步判断**,区别只在于"怎么求首次登录日"和"怎么判断次日":

```text
① 找出每个玩家的首次登录日 first_date
② 判断该玩家是否存在一行 event_date = first_date + 1 天
③ 统计满足 ② 的玩家数 ÷ 总玩家数,ROUND(…, 2)
```

| 方法 | 求首次登录日 | 判断次日 | 特点 |
|------|-------------|---------|------|
| ① MIN + 自连接 | `GROUP BY` + `MIN` | 自连接 | 最直观,MySQL 5.7 也能用 |
| ② 窗口 `MIN() OVER` | 窗口函数 | 同行比较 | **推荐**,一次扫描 |
| ③ 窗口 `ROW_NUMBER` + `LEAD` | 排序编号 + 偏移 | 看"下一行" | 展示偏移函数 |
| ④ `ROW_NUMBER` + 自连接 | 排名函数 | 自连接 | 排名函数经典用法 |
| ⑤ `EXISTS` 相关子查询 | 相关子查询 | 存在性 | 换一种判断方式 |

# 解题过程

> 这些方法具体怎么运用？

## 方法①:MIN + 自连接(最直观)

**第 1 步** —— 用 `GROUP BY` 求出每个玩家的首次登录日,得到派生表 `f`:

```sql
SELECT player_id, MIN(event_date) AS first_date
FROM Activity GROUP BY player_id;
```

```text
派生表 f
+-----------+------------+
| player_id | first_date |
+-----------+------------+
| 1         | 2016-03-01 |
| 2         | 2017-06-25 |
| 3         | 2016-03-02 |
+-----------+------------+
```

**第 2 步** —— 拿 `f` 去 `Activity` 里找"首次登录日 + 1 天"的记录(自连接):

```text
f 的每一行,去 Activity 里找 b.event_date = f.first_date + 1 天

玩家 1: first_date=2016-03-01 → 找 2016-03-02 → 找到了(玩家1的那行)✓ 匹配
玩家 2: first_date=2017-06-25 → 找 2017-06-26 → 没有 ✗ 丢弃
玩家 3: first_date=2016-03-02 → 找 2016-03-03 → 没有 ✗ 丢弃

JOIN 后结果
+-----------+------------+-----------+
| player_id | first_date | event_date|
+-----------+------------+-----------+
| 1         | 2016-03-01 | 2016-03-02|   ← 只剩这一行
+-----------+------------+-----------+
```

**第 3 步** —— 分子 `COUNT(DISTINCT player_id)` = 1;分母 `COUNT(DISTINCT player_id) FROM Activity` = 3:

```sql
SELECT ROUND(
           COUNT(DISTINCT b.player_id) * 1.0
           / (SELECT COUNT(DISTINCT player_id) FROM Activity),
           2
       ) AS fraction
FROM (SELECT player_id, MIN(event_date) AS first_date
      FROM Activity GROUP BY player_id) f
JOIN Activity b
  ON b.player_id = f.player_id
 AND b.event_date = DATE_ADD(f.first_date, INTERVAL 1 DAY);
```

```text
+----------+
| fraction |
+----------+
| 0.33     |
+----------+
```

> **为什么用 `JOIN` 而不是 `LEFT JOIN`？**
> 内连接只保留"匹配上"的行,天然就是"次日也登录了"的玩家;用 `LEFT JOIN` 的话没匹配上的玩家会以 `NULL` 保留,必须额外加 `WHERE b.event_date IS NOT NULL`。

> **为什么要 `* 1.0`？**
> MySQL 里整数 `/` 整数是**整数除法**（`1/3 = 0`）。乘 `1.0` 转成浮点,才是 `0.3333…`。

## 方法②:窗口函数 `MIN() OVER`(推荐)

这是**最像"给每行加一列"**的写法,不用自连接、不用派生表。

```sql
MIN(event_date) OVER (PARTITION BY player_id) AS first_date
```

**它做了什么** —— 按 `player_id` 分组,取组内 `event_date` 的最小值,**写回每一行**(注意:**行数不变**):

```text
执行窗口函数前                执行 MIN(event_date) OVER (PARTITION BY player_id) 后
+-----------+------------+    +-----------+------------+------------+
| player_id | event_date |    | player_id | event_date | first_date |
+-----------+------------+    +-----------+------------+------------+
| 1         | 2016-03-01 |    | 1         | 2016-03-01 | 2016-03-01 | ← 组内最小
| 1         | 2016-03-02 | →  | 1         | 2016-03-02 | 2016-03-01 | ← 同一个值
| 2         | 2017-06-25 |    | 2         | 2017-06-25 | 2017-06-25 |
| 3         | 2016-03-02 |    | 3         | 2016-03-02 | 2016-03-02 |
| 3         | 2018-07-03 |    | 3         | 2018-07-03 | 2016-03-02 |
+-----------+------------+    +-----------+------------+------------+
      5 行                                5 行(没有折叠!)
```

**逐行判断**:`event_date = first_date + 1 天`?

```text
+-----------+------------+------------+--------------------------+
| player_id | event_date | first_date | 是次日?                  |
+-----------+------------+------------+--------------------------+
| 1         | 2016-03-01 | 2016-03-01 | 03-02 vs 03-02 → ✗       |
| 1         | 2016-03-02 | 2016-03-01 | 03-02 vs 03-02 → ✓       | ← 玩家1 算数
| 2         | 2017-06-25 | 2017-06-25 | 06-26 vs 06-25 → ✗       |
| 3         | 2016-03-02 | 2016-03-02 | 03-03 vs 03-02 → ✗       |
| 3         | 2018-07-03 | 2016-03-02 | 03-03 vs 07-03 → ✗       |
+-----------+------------+------------+--------------------------+
```

完整 SQL:

```sql
WITH first_day AS (
    SELECT player_id, event_date,
           MIN(event_date) OVER (PARTITION BY player_id) AS first_date
    FROM Activity
)
SELECT ROUND(
           COUNT(DISTINCT CASE WHEN event_date = DATE_ADD(first_date, INTERVAL 1 DAY)
                               THEN player_id END) * 1.0
           / COUNT(DISTINCT player_id),
           2
       ) AS fraction
FROM first_day;
```

> **`COUNT(CASE WHEN … THEN player_id END)` 的技巧**
> 不写 `ELSE` 时,不满足条件的行返回 `NULL`,而 **`COUNT(列)` 会忽略 `NULL`**——所以 `COUNT` 出来的正好是满足条件的玩家数。等价写法:`SUM(CASE WHEN … THEN 1 ELSE 0 END)`。

## 方法③:`ROW_NUMBER` + `LEAD`(看"下一行")

`LEAD(col)` 取**排序后下一行**的 `col` 值(`NULL` 表示没有下一行)。于是"首次登录的次日也登录" ⟺ `rn = 1` 且 `next_date = event_date + 1 天`。

```text
ROW_NUMBER() OVER (PARTITION BY player_id ORDER BY event_date)  +  LEAD(event_date) OVER (同)
+-----------+------------+----+-----------+
| player_id | event_date | rn | next_date |
+-----------+------------+----+-----------+
| 1         | 2016-03-01 | 1  | 2016-03-02|  ← rn=1 且 next = +1天 ✓ 玩家1
| 1         | 2016-03-02 | 2  | NULL      |
| 2         | 2017-06-25 | 1  | NULL      |  ← 没有下一行 ✗
| 3         | 2016-03-02 | 1  | 2018-07-03|  ← next 差太远 ✗
| 3         | 2018-07-03 | 2  | NULL      |
+-----------+------------+----+-----------+
```

```sql
WITH ranked AS (
    SELECT player_id, event_date,
           ROW_NUMBER() OVER (PARTITION BY player_id ORDER BY event_date) AS rn,
           LEAD(event_date) OVER (PARTITION BY player_id ORDER BY event_date) AS next_date
    FROM Activity
)
SELECT ROUND(
           COUNT(DISTINCT CASE WHEN rn = 1
                                AND next_date = DATE_ADD(event_date, INTERVAL 1 DAY)
                               THEN player_id END) * 1.0
           / (SELECT COUNT(DISTINCT player_id) FROM Activity),
           2
       ) AS fraction
FROM ranked;
```

## 方法④:`ROW_NUMBER` + 自连接

把同一张表**编号两次**:`a` 取第 1 行(首次登录),`b` 取第 2 行(第二次登录),比较两者日期。

```text
编号后自连接 a.rn=1 与 b.rn=2

+-----------+------------+------------+-----------------------+
| player_id | a.event_date| b.event_date| 相差正好 1 天?        |
+-----------+------------+------------+-----------------------+
| 1         | 2016-03-01 | 2016-03-02 | 差 1 天 → ✓ 玩家1     |
| 2         | 2017-06-25 | NULL       | b 为 NULL → ✗         |
| 3         | 2016-03-02 | 2018-07-03 | 差 853 天 → ✗         |
+-----------+------------+------------+-----------------------+
```

```sql
SELECT ROUND(
           COUNT(DISTINCT CASE WHEN b.event_date = DATE_ADD(a.event_date, INTERVAL 1 DAY)
                               THEN a.player_id END) * 1.0
           / (SELECT COUNT(DISTINCT player_id) FROM Activity),
           2
       ) AS fraction
FROM (SELECT player_id, event_date,
             ROW_NUMBER() OVER (PARTITION BY player_id ORDER BY event_date) AS rn
      FROM Activity) a
LEFT JOIN (SELECT player_id, event_date,
                  ROW_NUMBER() OVER (PARTITION BY player_id ORDER BY event_date) AS rn
           FROM Activity) b
  ON a.player_id = b.player_id AND b.rn = 2
WHERE a.rn = 1;
```

> 这里必须 `LEFT JOIN`:只登录过一次的玩家(没有第 2 行)也要留在结果里,其 `b.event_date` 为 `NULL`,`CASE` 自然不成立。

## 方法⑤:`EXISTS` 相关子查询

```sql
SELECT ROUND(
           COUNT(DISTINCT CASE WHEN EXISTS (
                    SELECT 1 FROM Activity x
                    WHERE x.player_id = a.player_id
                      AND x.event_date = DATE_ADD(a.event_date, INTERVAL 1 DAY)
                ) THEN a.player_id END) * 1.0
           / (SELECT COUNT(DISTINCT player_id) FROM Activity),
           2
       ) AS fraction
FROM Activity a
WHERE a.event_date = (SELECT MIN(event_date) FROM Activity y WHERE y.player_id = a.player_id);
```

`EXISTS` 只关心"有没有行",所以子查询里写 `SELECT 1` 就够了。缺点是**相关子查询对外层每一行都要执行一次**,大表上比方法②慢得多。

# 窗口函数详解

> 这一节把 `OVER()` 讲清楚。

## 一、它和 `GROUP BY` 的本质区别

```text
GROUP BY:把每组"压成一行"(行数变少)
+-----------+------------+
| player_id | MIN(date)  |
+-----------+------------+
| 1         | 2016-03-01 |   3 行 ← 5 行原始数据被折叠成 3 行
| 2         | 2017-06-25 |
| 3         | 2016-03-02 |
+-----------+------------+

窗口函数:给每行"附加一列"(行数不变)
+-----------+------------+------------+
| player_id | event_date | first_date |
+-----------+------------+------------+
| 1         | 2016-03-01 | 2016-03-01 |   5 行 ← 一行都没少
| 1         | 2016-03-02 | 2016-03-01 |
| 2         | 2017-06-25 | 2017-06-25 |
| 3         | 2016-03-02 | 2016-03-02 |
| 3         | 2018-07-03 | 2016-03-02 |
+-----------+------------+------------+
```

一句话:**`GROUP BY` 是"折叠",窗口函数是"加列"**。正因为不折叠,才能在一行里同时看到"本次登录日期"和"首次登录日期",从而直接比较。

## 二、`OVER()` 的三个组成部分

```sql
函数名(...) OVER (
    PARTITION BY 分区列      -- ① 把数据切成若干"窗口"(可省略 → 全表一个窗口)
    ORDER BY    排序列       -- ② 窗口内排序(可省略)
    ROWS BETWEEN ... AND ... -- ③ 窗口帧(可省略,有默认值)
)
```

**① `PARTITION BY player_id`** —— 相当于"分组",但**不合并行**。每个玩家是一个独立窗口,函数只在窗口内计算。不写 `PARTITION BY` 则整张表是一个窗口。

**② `ORDER BY event_date`** —— 决定窗口内的顺序。对 `ROW_NUMBER`/`RANK`/`LEAD`/`LAG` 是**必需**的(否则"第几行""下一行"无从谈起);对 `SUM`/`MIN`/`MAX` 则会改变"累计"的范围(见下)。

**③ 窗口帧** —— 决定"当前行能看到窗口内的哪些行":

```text
默认规则:
  有 ORDER BY  → RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
                 (从窗口第一行到"当前行",即累计)
  无 ORDER BY  → 整个窗口

示例(窗口内 event_date 升序):
  行1  累计到 行1   ┐
  行2  累计到 行2   ├ 有 ORDER BY:SUM 是"累计和"
  行3  累计到 行3   ┘
```

本例的 `MIN(event_date) OVER (PARTITION BY player_id)` **没有 `ORDER BY`**,所以帧是整个窗口 → 拿到的是"该玩家所有行的最小值",正是我们要的首次登录日。

> ⚠️ **如果误加了 `ORDER BY`**:
> `MIN(event_date) OVER (PARTITION BY player_id ORDER BY event_date)`
> 帧变成"从第一行到当前行",而按日期升序时第一行就是最小日期,所以结果**碰巧还是对的**——但这是巧合,依赖排序方向。反过来写 `ORDER BY event_date DESC` 就会得到"当前行为止的最小值",语义完全不同。**不需要累计时,别乱加 `ORDER BY`。**

## 三、常用窗口函数分类

| 类别 | 函数 | 作用 |
|------|------|------|
| 聚合类 | `SUM / AVG / COUNT / MIN / MAX ... OVER()` | 窗口内的聚合值,附到每行 |
| 排名类 | `ROW_NUMBER()` | 1,2,3… 无并列(必定唯一) |
| | `RANK()` | 1,2,2,4… 并列跳号 |
| | `DENSE_RANK()` | 1,2,2,3… 并列不跳号 |
| | `NTILE(n)` | 均分成 n 桶 |
| 偏移类 | `LAG(col, n)` | 往前看第 n 行(默认 n=1) |
| | `LEAD(col, n)` | 往后看第 n 行 |
| | `FIRST_VALUE / LAST_VALUE / NTH_VALUE` | 窗口内第 1 / 最后 / 第 n 个值 |

本例用到的:`MIN() OVER`(聚合类)、`ROW_NUMBER()`(排名类)、`LEAD()`(偏移类)。

## 四、排名三兄弟的区别(常考)

数据 `[10, 20, 20, 30]`:

```text
值      10   20   20   30
ROW_NUMBER()   1    2    3    4     ← 并列也给不同编号(顺序不确定)
RANK()         1    2    2    4     ← 并列同名,下一个跳号
DENSE_RANK()   1    2    2    3     ← 并列同名,下一个不跳号
```

## 五、窗口函数 vs 其他写法的取舍

| | 可读性 | 性能 | 版本要求 |
|---|---|---|---|
| `GROUP BY` + 自连接 | 中 | 中(多一次扫描) | 所有版本 |
| 窗口函数 | **高** | **好(一次扫描)** | MySQL 8.0+ |
| 相关子查询 `EXISTS` | 中 | 差(逐行执行) | 所有版本 |

# 复杂度

- 时间:方法②③④ 为 $O(n \log n)$(窗口内排序主导);方法① 为 $O(n \log n)$ + 一次连接;方法⑤ 最坏 $O(n^2)$(相关子查询)。
- 空间:$O(n)$(窗口/派生表需要物化中间结果)。

# 易错点

1. **整数除法**:`COUNT(...) / COUNT(...)` 在 MySQL 里是整数除法,`1/3 = 0`。必须 `* 1.0` 或 `CAST(... AS DECIMAL)`。
2. **分母要 `COUNT(DISTINCT player_id)`**:一个玩家有多条登录记录,不 `DISTINCT` 会把记录数当人数。
3. **分子也要 `DISTINCT`**:一个玩家可能有多条"次日"记录(比如连登 3 天),不 `DISTINCT` 会重复计数。
4. **`+ INTERVAL 1 DAY` 与 `DATEDIFF` 的区别**:前者是日期运算(能跨月/跨年/处理闰年),后者只算天数差。用 `DATEDIFF(b.date, a.date) = 1` 也可以,但要保证参数顺序。
5. **别用 `LEFT JOIN` 后又忘了 `IS NOT NULL`**:会把所有"只登录一次"的玩家也算进分子。
6. **窗口函数里乱加 `ORDER BY`**:如第 3 节所述,会悄悄改变窗口帧语义(本例碰巧不出错,但换个排序方向就错)。
7. **空表 / 分母为 0**:MySQL 和 SQLite 返回 `NULL`(不是报错);如果判题要求返回 0,需要 `IFNULL(..., 0)`。

扩展样例的构造(注意闰年与平年的区别):

```text
玩家 1: 01-01, 01-02                → 次日 ✓

                                       6 / 8 = 0.75
```
